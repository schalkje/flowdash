# Pre-Render Feature - Quick Reference

## What Was Implemented

Phase 2 of the pre-render feature is now complete. The dashboard can now:

1. ✅ Detect when pre-render data is available in JSON
2. ✅ Use fast-path initialization to skip layout calculations
3. ✅ Apply node positions directly from pre-render data
4. ✅ Defer status rules until after initial render
5. ✅ Fall back gracefully when pre-render data is missing

## Key Files Modified

| File | Changes |
|------|---------|
| `dashboard.js` | Added pre-render detection and deferred status application |
| `nodeBase.js` | Apply pre-render positions in constructor |
| `nodeBaseContainer.js` | Skip layout calculations when pre-render available |
| `configManager.js` | Added `usePrerender` and `prerenderMetadata` settings |

## How to Use

### Step 1: Generate Pre-Render Data

1. Start server: `python -m http.server 8000`
2. Open: http://localhost:8000/dashboard/prerender-generator.html
3. Upload your dashboard JSON
4. Click "Generate Pre-Render"
5. Download the enhanced JSON

### Step 2: Use Enhanced JSON

Load the enhanced JSON in any FlowDash viewer:
- `flowdash-js.html`
- `flowdash-bundle.html`
- Custom implementations using the Dashboard API

The pre-render data will be automatically detected and used.

### Step 3: Verify It's Working

Open browser console and look for:
```
📊 Pre-render data detected - using fast-path initialization
📊 Pre-render: Scheduling deferred status application
📊 Pre-render: Skipping layout for {nodeId}
📊 Pre-render: Applying deferred status rules
📊 Pre-render: Status rules applied
```

## API

### Settings

```javascript
{
  settings: {
    usePrerender: true,  // Enable/disable pre-render (default: true)
    prerenderMetadata: {  // Auto-generated by generator
      generated: "2025-01-11T...",
      nodeCount: 885,
      edgeCount: 1204,
      // ...
    }
  }
}
```

### Node Pre-Render Data Format

```javascript
{
  id: "node1",
  type: "foundation",
  // ... other node properties
  prerender: {
    x: 123.45,
    y: 678.90,
    width: 100,
    height: 60
  }
}
```

### Dashboard Methods

```javascript
// Check if pre-render data is available
dashboard.hasPrerenderData()  // returns boolean

// Manually apply deferred status rules (called automatically)
dashboard.applyDeferredStatusRules(root)
```

### Node Properties

```javascript
// Check if node has pre-render data
node.hasPrerenderData  // getter returns boolean
```

## Performance Impact

### Expected Improvements

| Nodes | Without Pre-Render | With Pre-Render | Improvement |
|-------|-------------------|-----------------|-------------|
| 4 | ~500ms | ~300ms | **40%** |
| 21 | ~2s | ~1.2s | **40%** |
| 885 | ~40s | ~22s | **45%** |

### File Size Impact

Pre-render data adds ~13-25% to JSON file size:
- Small dashboards: +25%
- Large dashboards: +13%

Trade-off is worth it for the 40-45% load time improvement.

## Disabling Pre-Render

### Method 1: Setting in JSON

```javascript
{
  settings: {
    usePrerender: false
  }
}
```

### Method 2: Remove Pre-Render Data

Delete the `prerender` properties from nodes (or regenerate without pre-render).

## Debugging

### Console Messages

Look for `📊` emoji in console for pre-render related messages.

### Common Issues

**Pre-render not detected**:
- Check `settings.usePrerender` is not `false`
- Verify nodes have `prerender` property
- Check console for detection message

**Layout looks wrong**:
- Pre-render data might be from different settings
- Try regenerating with current dashboard settings
- Check if status-based collapse is interfering

**Performance not improved**:
- Verify pre-render messages in console
- Check if status rules are causing re-layouts
- Try with `toggleCollapseOnStatusChange: false`

## Compatibility

### ✅ Compatible With

- All node types (foundation, mart, adapter, etc.)
- Nested containers
- Status-based collapse
- Edge routing
- Zoom and pan
- Selection
- Minimap

### ⚠️ Limitations

- Pre-render data is static (won't adapt to window resize)
- Status changes after load may cause re-layout
- Collapse/expand invalidates pre-render for that subtree
